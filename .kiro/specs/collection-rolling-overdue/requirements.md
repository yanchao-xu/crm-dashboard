# Requirements Document

## Introduction

本功能实现 CRM Dashboard 中的回款滚动与逾期逻辑。系统需对比计划回款时间与当前日期来判定逾期状态，并在月底自动将未回款金额滚动至下一期。柱状图需以分色叠加的方式同时展示当月原生计划回款和历史逾期滚动金额，并支持交互式下钻查看合同详情。

## Glossary

- **回款管理系统 (Collection_System)**: 负责逾期判定、金额滚动计算和图表数据生成的核心模块
- **计划回款时间 (Planned_Collection_Date)**: 应收计划（ReceivablePlan）中的 plannedDate 字段
- **实际回款金额 (Actual_Collection_Amount)**: 应收计划（ReceivablePlan）中的 actualAmount 字段
- **计划回款金额 (Planned_Collection_Amount)**: 应收计划（ReceivablePlan）中的 plannedAmount 字段
- **当月原生计划 (Native_Plan)**: 该月份本身计划的应收金额（不含从前期滚动过来的逾期金额）
- **滚动逾期金额 (Rolled_Overdue_Amount)**: 从前期因未回款而累积滚动至当月的逾期金额
- **应收总额 (Total_Receivable)**: 等于当月原生计划加上历史累积逾期未回款金额
- **滚动来源标记 (Rolling_Source_Tag)**: 标识某笔逾期金额最初来源于哪个月份的计划
- **回款柱状图 (Collection_Bar_Chart)**: 按月展示分色叠加柱状图的组件
- **合同列表 (Contract_List)**: 点击柱状图后展示该月所有相关合同明细的列表

## Requirements

### Requirement 1: 逾期判定

**User Story:** 作为销售经理，我希望系统能自动识别逾期的应收计划，以便我能及时对延迟回款采取行动。

#### Acceptance Criteria

1. 当 当前日期超过计划回款时间（即当前日期 > plannedDate，以自然日为粒度比较）且 实际回款金额等于零 时，回款管理系统 应将该应收计划标记为"逾期"状态。
2. 当 当前日期超过计划回款时间 且 实际回款金额大于零但小于计划回款金额 时，回款管理系统 应将该应收计划的未收回部分（plannedAmount 减去 actualAmount）标记为"逾期"状态。
3. 当 应收计划已逾期 且 实际回款发生在计划回款时间所在的同一自然月内（即 actualDate 与 plannedDate 属于同一年月） 时，回款管理系统 应保留该计划的"逾期"状态标签，并将该计划保留在原月份的统计中，不滚动至下一月。
4. 当 应收计划已逾期 且 实际回款发生在计划回款时间所在月份的最后一天之后（即 actualDate 超过 plannedDate 所在月份最后一天） 时，回款管理系统 应将该计划标记为需要滚动至下一期。
5. 当 应收计划已逾期 且 在计划回款时间所在月份最后一天之前收到全额回款（actualAmount >= plannedAmount） 时，回款管理系统 应将合同状态更新为"已完成"，保留逾期标签用于统计，但不产生任何滚动逾期金额。

### Requirement 2: 自动滚动机制

**User Story:** 作为财务分析师，我希望未回款金额能自动滚入下一月目标，以便累积的回款缺口始终清晰可见。

#### Acceptance Criteria

1. 当 应收计划的 plannedYearMonth 早于系统当前自然月（以系统时钟判定） 且 实际回款金额（actualAmount）小于计划回款金额（plannedAmount） 时，回款管理系统 应将未收回余额（plannedAmount 减去 actualAmount，结果四舍五入至整数）滚动至紧邻的下一个财年月份的应收总额目标中。
2. 回款管理系统 应将每月的应收总额（Total_Receivable）计算为：当月原生计划金额（该月 plannedYearMonth 匹配的所有应收计划 plannedAmount 之和）加上 所有从前期累积滚动至该月且尚未收回的滚动逾期金额之和。
3. 当 某笔滚动逾期金额在其滚动目标月份结束时仍未收回（即该月 actualAmount 仍小于滚动逾期金额） 时，回款管理系统 应将剩余未收回余额继续向后滚动至再下一个财年月份（例如：6月逾期滚至7月，7月仍未收回则滚至8月，以此类推），直到该笔金额被完全收回或到达财年最后一个月。
4. 回款管理系统 应为每笔滚动逾期金额附加滚动来源标记（Rolling_Source_Tag），记录该笔逾期最初来源于哪个月份的计划（以 plannedYearMonth 格式标识，如 "2026-04"）。
5. 当 针对已滚动的应收计划收到部分回款（actualAmount 增加但仍小于累计滚动逾期金额） 时，回款管理系统 应将滚动逾期金额减去实际收到的回款金额，仅将剩余正数余额继续滚动至下一个财年月份。
6. 回款管理系统 应将所有 actualAmount 小于 plannedAmount 且 plannedYearMonth 早于当前自然月的应收计划视为需要滚动，无论 actualAmount 为零还是大于零的部分回款。
7. 如果 某笔应收计划的 actualAmount 大于或等于 plannedAmount，则 回款管理系统 不应对该笔计划产生任何滚动逾期金额，即使 actualAmount 等于 plannedAmount 时余额为零也不生成滚动记录。
8. 回款管理系统 应在每次页面加载或筛选条件变更时，基于当前所有应收计划数据动态重新计算滚动逾期金额，而非依赖预存储的滚动状态。

### Requirement 3: 柱状图可视化

**User Story:** 作为销售经理，我希望看到一个分色叠加柱状图来区分原生计划金额和滚动逾期金额，以便我能快速了解每月回款目标的构成。

#### Acceptance Criteria

1. 回款柱状图 应将每月的柱状图显示为两个颜色分段的叠加柱：底部蓝色段代表当月原生计划金额，顶部橙色段代表滚动逾期金额；当某一分段金额为零时，该分段不渲染。
2. 回款柱状图 应将柱子的总高度显示为每月的当月原生计划与滚动逾期金额之和，X 轴显示 12 个财年月份标签。
3. 当 用户将鼠标悬停在柱状图的任意分段上 时，回款柱状图 应在 300 毫秒内显示一个工具提示，展示该月的当月原生计划金额、滚动逾期金额和应收总额，金额按当前选定币种格式化显示。
4. 回款柱状图 应渲染一个图例，包含两个条目：蓝色色块标注为当月原生计划回款，橙色色块标注为前期滚动过来的逾期累积金额。
5. 如果 某月的当月原生计划金额和滚动逾期金额均为零，则 回款柱状图 应为该月渲染高度为零的柱位且保留 X 轴月份标签。

### Requirement 4: 图表交互与合同列表下钻

**User Story:** 作为销售经理，我希望点击柱状图中的柱子后能看到该月的合同详细列表，以便我能识别具体的逾期合同。

#### Acceptance Criteria

1. WHEN 用户点击 Collection_Bar_Chart 中某月的柱子（整根柱子区域）时，THE Contract_List SHALL 在 500 毫秒内展示与该月相关的所有合同，包括当月原生计划合同和历史逾期滚动至该月的合同，列表最多展示 200 条合同记录。
2. WHEN Contract_List 中的某份合同来自前期逾期滚动（即该合同的原始计划月份早于当前选中月份）时，THE Contract_List SHALL 在该合同行中显示一个可视逾期标识徽章和 Rolling_Source_Tag，Rolling_Source_Tag 中显示该合同的原始计划月份（格式为"YYYY-MM"）。
3. WHEN 用户点击 Collection_Bar_Chart 中某月柱子的橙色（逾期）部分时，THE Contract_List SHALL 筛选为仅显示滚动至该月的逾期合同，排除当月原生计划合同。
4. WHEN 用户点击 Collection_Bar_Chart 中某月柱子的蓝色（原生计划）部分时，THE Contract_List SHALL 筛选为仅显示该月的原生计划合同，排除滚动逾期合同。
5. IF 用户点击某月的柱子后该月无关联合同数据，THEN THE Contract_List SHALL 显示空状态提示信息，表明该月无合同记录。
6. WHEN 用户再次点击已选中的同一柱子时，THE Contract_List SHALL 清除筛选条件，恢复为展示全部合同的默认状态。

### Requirement 5: 关键字段

**User Story:** 作为开发者，我希望数据模型包含逾期和滚动逻辑所需的所有字段，以便系统能正确计算和展示回款状态。

#### Acceptance Criteria

1. 回款管理系统 应为每笔应收计划维护以下字段：计划回款时间（plannedDate）、计划回款金额（plannedAmount，取值范围 0.01 至 999,999,999.99）、实际回款时间（actualDate）、实际回款金额（actualAmount，取值范围 0 至 999,999,999.99）、合同状态（正常/即将到期/逾期/已完成）、滚动来源标记（格式为原始逾期所属年月，如"2024-03"）。
2. 当 应收计划的计划回款时间早于当前日期 且 实际回款金额为0 时，回款管理系统 应将合同状态字段更新为"逾期"。
3. 当 应收计划的计划回款时间距当前日期在14个自然日以内（含第0天和第14天） 且 实际回款金额为0 时，回款管理系统 应将合同状态设置为"即将到期"。
4. 如果 应收计划的实际回款金额大于0 但 小于计划回款金额 且 计划回款时间早于当前日期，则 回款管理系统 应将合同状态设置为"逾期"并保留未清余额（计划回款金额减去实际回款金额）用于滚动计算。
5. 回款管理系统 应在合同列表中将滚动来源标记作为只读文本列展示，显示该笔逾期金额最初产生的年月（格式"YYYY-MM"），以便用户识别逾期来源月份。
